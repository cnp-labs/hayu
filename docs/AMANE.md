## Verified lifecycle and redraw findings

- **Startup assembles views then hands control to Wayland backend.** `App::run` validates windows, sets font, creates GPU lifetime guard, initializes `WaylandApp`, then runs it ([`src/app.rs:89-119`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/app.rs#L89-L119)). Amane uses SCTK/calloop; this is documented in [`ARCHITECTURE.md#startup`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/ARCHITECTURE.md#startup).
- **Surface state is per open surface.** `OpenWindow` contains view, output, configured dimensions/scales, frame-request flag, service dependencies, input state, GPU, fractional-scale object and protocol role ([`src/wayland/surface.rs:25-85`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/surface.rs#L25-L85)). Roles discriminate layer, lock and xdg normal windows. Window opening creates Wayland surface, runs initial view at 0×0 to obtain layer settings, creates role, and initializes GPU ([`src/wayland/windows.rs:18-54`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/windows.rs#L18-L54), [`:57-100`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/windows.rs#L57-L100)).
- **Frame pipeline.** `OpenWindow::redraw` reruns view, replaces dependency set, diffs surface settings, exits before widget build when dimensions are zero, lays out/draws and collects input targets, requests another callback if moving, then presents ([`src/wayland/redraw.rs:11-90`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/redraw.rs#L11-L90)). `frame::run_view` resets per-frame read/motion tracking; `frame::build` records widget commands and hit targets and returns moving state ([`src/frame.rs:23-89`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/frame.rs#L23-L89)).
- **Wayland callback gating/coalescing.** `request_frame` immediately reruns view for width-zero hidden/unconfigured window, otherwise deduplicates with `frame_requested`, requests `wl_surface.frame`, commits; multiple changes before callback share one upcoming frame ([`src/wayland/redraw.rs:92-124`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/redraw.rs#L92-L124)). Compositor callback clears flag and calls redraw ([`src/wayland/compositor.rs:39-47`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/compositor.rs#L39-L47)).
- **Hidden surface behavior.** A hidden layer surface detaches buffer and commits, zeros width/height and clears outstanding frame flag; comments state no drawing until show causes fresh configure ([`src/wayland/update.rs:92-104`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/update.rs#L92-L104)). Settings are compared before protocol updates; visible false triggers hide, visible true reapplies settings and commits without buffer to solicit configure ([`src/wayland/update.rs:15-60`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/update.rs#L15-L60)). Initial hidden window never gets configure; source comment notes first-view dependencies are what can wake it ([`src/wayland/windows.rs:22-27`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/windows.rs#L22-L27)).
- **Targeted change propagation.** Views record `TypeId` of services read. Change marks are mutex-protected and ping calloop; wake callback processes open/close/lock and requests affected frames ([`src/changes.rs:36-92`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/changes.rs#L36-L92), [`src/wayland/wake.rs:7-25`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/wake.rs#L7-L25)). A window redraws iff its reads overlap changed IDs; input can request only source surface ([`src/wayland/windows.rs:109-138`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/windows.rs#L109-L138)). Service trait defaults to interval polling on its own thread, but event-driven implementations can replace listener ([`src/services.rs:44-97`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/services.rs#L44-L97)).
- **Animation scheduling.** `Animation::value` sets global moving flag until progress reaches one; `to` starts from current interpolated value, avoiding jump ([`src/animation.rs:58-95`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/animation.rs#L58-L95)). Frame consumes flag after widget drawing; redraw asks for next compositor callback only when moving ([`src/frame.rs:69-88`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/frame.rs#L69-L88), [`src/wayland/redraw.rs:62-69`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/redraw.rs#L62-L69)). Thus animation is refresh-paced, not independent timer. **Inference:** global motion flag is safe under single-thread view/draw sequencing described in architecture, but would need per-window tracking in concurrently drawn windows.
- **Renderer boundary.** Widgets append commands to a transform-aware recorder ([`src/graphics/renderer.rs:11-94`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/graphics/renderer.rs#L11-L94)); GPU consumes finished command list at presentation ([`src/wayland/redraw.rs:131-158`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/src/wayland/redraw.rs#L131-L158)). Architecture describes per-window GPU objects with shared device/renderer, cheap quad path for common primitives and Vello for complex paths/effects ([`ARCHITECTURE.md#drawing`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/ARCHITECTURE.md#drawing)). Cargo pins dependency families including `vello`, `wgpu`, SCTK ([`Cargo.toml`](https://github.com/MystiaFin/amane/blob/544cbfc23af37f84ac237cd9bec53173981772b3/Cargo.toml)).

## Hayu relevance

**Compatible patterns to consider as design references (not code reuse):** callback-driven frame pacing; one outstanding frame request per surface; per-surface dependency/redraw scope; explicit hidden-state buffer detach and zero-size guard; settings diff before protocol traffic; renderer command recording separating widget/layout logic from GLES execution; animation requests next frame only while active; keeping Wayland and draw operations on event-loop thread, workers only signal changes. These align with Hayu's specialized event-driven GLES/glow architecture and existing constraints.

**Unsuitable to transplant:** Amane's immediate-mode rebuilding of full widget tree, broad public generic widget toolkit, global typed `Service` store with one thread per service/default polling, wholesale replacement of Hayu's existing SCTK/calloop integration, wgpu/Vello renderer and shared GPU setup. Hayu already has its own narrow widget/frame model, Hyprland adapter ownership, calloop event loop and GLES/EGL per-output contexts. Service read-tracking or abstractions would add complexity unless measured need appears. Animation global flag also assumes its own sequencing; adapt only as per-surface scheduling state if needed. No evidence here establishes performance superiority for Hayu.
